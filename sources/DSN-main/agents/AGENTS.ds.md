## DS-Ngr rules

This app is built on the **DS-Ngr** design system (React + Vite + TypeScript).

### Before writing any UI code
1. Read `node_modules/ds-ngr/AI.md` — component usage, layout rules, tokens and patterns. It is the source of truth. If it isn't there yet, run `npm install` first.
2. Use DS-Ngr components from `ds-ngr`. Don't build replacements from raw HTML.
3. Never invent props: check the component's types in `node_modules/ds-ngr/dist`.
4. Before using a component, read its spec at `node_modules/ds-ngr/src/components/<tier>/<Name>/<Name>.spec.md` (when to use it, variants, common mistakes). `node_modules/ds-ngr/ds-index.json` lists every component with its tier and spec path.
5. For a full page, start from `node_modules/ds-ngr/specs/patterns/` (data page, dashboard, form page, detail drawer, kanban board) and the runnable examples in `node_modules/ds-ngr/templates/`.

### Styling
- Style with DS-Ngr tokens (`var(--space-*)`, `var(--color-*)`, `var(--font-size-*)`). No hex colours, raw px spacing, or `font-family`.
- Icons come from `lucide-react`, which is bundled with `ds-ngr`. Never add `lucide-react` to package.json.
- Keep the CSS import order in `src/main.tsx`: `ds-ngr/tokens.css` → the theme file in `src/styles/` → `./styles/overrides.css` → `ds-ngr/global.css` → `ds-ngr/style.css`.

### Tokens and theme
- Every token is defined in `node_modules/ds-ngr/dist/tokens.css`. Never edit it, and never copy it into the app.
- The theme file in `src/styles/` is generated by the DS-Ngr theme configurator. Don't edit it by hand — re-export it from the configurator.
- To change any token by hand, re-value it in `src/styles/overrides.css`. Prefer semantic tokens (`--color-*`, `--space-*`) for one-off changes and `--primitive-*` for a whole colour ramp. Dark-only values go under `:root[data-theme="dark"]`.
- Never invent token names: a token only works if it is declared in `tokens.css`.
